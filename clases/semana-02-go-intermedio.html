Semana 02 · Bloque I: Dominando Go

Go Intermedio para Construir Intérpretes

Hoy dominaremos los 4 patrones arquitectónicos que Thorsten Ball utiliza en cada capítulo del libro: Structs + Punteros, Interfaces implícitas, Funciones de primera clase y Table-Driven Testing.

Duración: Semana 2 (2 sesiones) Puente directo hacia Cap. 1–4 Enfoque: Desarrollo Guiado por Pruebas (TDD)

1. Structs y Funciones Constructoras

Go no tiene clases ni herencia. Agrupamos datos relacionados con struct y definimos una función convencional llamada New(...) para inicializar instancias válidas.

scanner.go
type Token struct {
    Type    string
    Literal string
}

type Scanner struct {
    input    string
    position int
    ch       byte
}

// Convención en Go: función constructora New()
func New(input string) *Scanner {
    s := &Scanner{input: input}
    return s
}

¿Por qué no clases?

Go favorece la composición sobre la herencia. En lugar de árboles rígidos de clases padre/hijo:

  • Los datos viven en struct simples y planos.
  • El comportamiento se adjunta mediante métodos.
  • El polimorfismo se logra con interfaces pequeñas.

2. Punteros y Receivers: Valor vs Puntero

En Go, todo se pasa por valor (se hace una copia). Si un método necesita modificar el estado interno de un struct (como avanzar la posición del Lexer), debe usar un pointer receiver (*Tipo).

receivers.go
// [MAL] Value receiver: recibe una COPIA.
// Los cambios se pierden al salir de la función.
func (s Scanner) avanzarMal() {
    s.position++ // ¡Solo modifica la copia!
}

// [OK] Pointer receiver: recibe la DIRECCIÓN en memoria.
// Los cambios persisten en el Scanner original.
func (s *Scanner) avanzarBien() {
    s.position++
}

Operadores de Puntero en Go

SímboloSignificadoEjemplo
&xDirección de memoria de xp := &Scanner{}
*TTipo "puntero a T"func New() *Lexer
*pDesreferenciar (leer valor)valor := *p
nilPuntero vacío (sin objeto)if err != nil
Regla práctica para Monkey: Token es pequeño e inmutable → se pasa por valor. Lexer, Parser, Environment y los nodos del AST/Objetos → se pasan por puntero (*Lexer, *ast.Program, *object.Integer).

3. Interfaces Implícitas: El Corazón del AST y los Objetos

En Go no existe la palabra implements. Si un struct tiene todos los métodos declarados por una interfaz, automáticamente la satisface.

object_preview.go
// Definimos el contrato
type Object interface {
    Type() string
    Inspect() string
}

// Integer satisface Object implícitamente
type Integer struct {
    Value int64
}

func (i *Integer) Type() string    { return "INTEGER" }
func (i *Integer) Inspect() string { return fmt.Sprintf("%d", i.Value) }

// Boolean también satisface Object
type Boolean struct {
    Value bool
}

func (b *Boolean) Type() string    { return "BOOLEAN" }
func (b *Boolean) Inspect() string { return fmt.Sprintf("%t", b.Value) }

¿Por qué es tan poderoso en un Intérprete?

Gracias a las interfaces podremos escribir:

  • Eval(node ast.Node) object.Object — Una sola función acepta cualquier nodo del AST y devuelve cualquier valor de Monkey.
  • Statements []ast.Statement — Un slice puede mezclar sentencias let, return y expresiones.
  • Start(in io.Reader, out io.Writer) — Nuestro REPL funciona con consola, archivos o tests en memoria.

4. Type Assertions y Type Switches

Cuando recibimos un valor a través de una interfaz (por ejemplo node ast.Node), a menudo necesitamos descubrir su tipo concreto real para operar con sus campos.

type_assertion.go
// Type assertion segura ("comma ok")
// Muy usada en parser_test.go y evaluator_test.go
var obj Object = &Integer{Value: 42}

entero, ok := obj.(*Integer)
if !ok {
    fmt.Println("No era un Integer")
    return
}
fmt.Println("Valor:", entero.Value) // 42
type_switch.go (Así luce el Evaluador)
func describir(obj Object) string {
    switch v := obj.(type) {
    case *Integer:
        return fmt.Sprintf("Entero: %d", v.Value)
    case *Boolean:
        return fmt.Sprintf("Booleano: %t", v.Value)
    default:
        return "Tipo desconocido"
    }
}
Adelanto de la Semana 6: La función principal Eval(node ast.Node, env *object.Environment) es literalmente un gran switch node := node.(type) que inspecciona cada nodo del árbol y decide cómo evaluarlo.

5. Funciones de Primera Clase y Closures

En Go, las funciones son ciudadanos de primera clase: se pueden guardar en variables, pasar como argumentos y almacenar dentro de un map.

pratt_preview.go (Patrón exacto de la Semana 5)
// 1. Definimos un "tipo función"
type OperacionFn func(a, b int64) int64

// 2. Creamos una tabla de despacho (map de token -> función)
operadores := map[string]OperacionFn{
    "+": func(a, b int64) int64 { return a + b },
    "-": func(a, b int64) int64 { return a - b },
    "*": func(a, b int64) int64 { return a * b },
}

// 3. Buscamos y ejecutamos dinámicamente
if fn, ok := operadores["*"]; ok {
    fmt.Println(fn(6, 7)) // 42
}
¿Por qué importa esto? En el Pratt Parser (Semana 5), registraremos dos mapas: prefixParseFns e infixParseFns que mapean cada token.TokenType a la función encargada de parsearlo. ¡Cero switch gigantescos!

6. bytes.Buffer y bufio.Scanner

Dos utilidades de la biblioteca estándar aparecerán constantemente en nuestro intérprete:

bytes.Buffer (en ast.go)

Construye strings eficientemente sin crear copias intermedias en cada concatenación. Lo usaremos en el método String() de cada nodo del AST.

var out bytes.Buffer
out.WriteString("let ")
out.WriteString(nombre)
out.WriteString(" = ")
out.WriteString(valor)
out.WriteString(";")
return out.String()

bufio.Scanner (en repl.go)

Lee línea por línea desde cualquier io.Reader (como os.Stdin) de manera limpia y segura.

scanner := bufio.NewScanner(in)
for {
    fmt.Fprintf(out, ">> ")
    if !scanner.Scan() {
        return
    }
    line := scanner.Text()
    // Enviar line al Lexer / Parser / Eval
}

7. Testing Nativo y Table-Driven Tests

Todo el libro Writing An Interpreter In Go se construye con pruebas unitarias antes o junto al código. Go incluye el paquete testing sin instalar nada.

calc_test.go
package calc

import "testing"

func TestSumar(t *testing.T) {
    // Tabla de casos de prueba (Table-Driven Test)
    tests := []struct {
        a, b     int64
        expected int64
    }{
        {2, 3, 5},
        {-1, 1, 0},
        {10, 25, 35},
    }

    for i, tt := range tests {
        got := Sumar(tt.a, tt.b)
        if got != tt.expected {
            t.Fatalf("tests[%d] - esperado=%d, obtenido=%d",
                i, tt.expected, got)
        }
    }
}

Reglas del Testing en Go

  • El archivo debe terminar en _test.go.
  • Cada test empieza con Test... y recibe (t *testing.T).
  • t.Errorf(...) registra fallo y continúa; t.Fatalf(...) detiene ese test de inmediato.
  • Ejecutar todo el proyecto: 
    go test -v ./...
