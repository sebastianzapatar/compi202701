Patrones de Diseño I: Creacionales y Estructurales

Los patrones son soluciones probadas a problemas de diseño que se repiten. Veremos los 12 patrones creacionales y estructurales del catálogo clásico (GoF), cada uno con un programa Go ejecutable y su lugar dentro de ZeldaInterpreter.

12 programas en ejemplos/patrones/ Referencia: catálogo de Refactoring.Guru
1Reconocer el problema que resuelve cada patrón.
2Implementarlo de forma idiomática en Go (interfaces, funciones, embedding).
3Identificar dónde ya aparece en el intérprete.
4Saber cuándo no usarlo.

1. ¿Qué es un patrón de diseño?

Un patrón describe un problema recurrente, la idea de su solución y sus consecuencias. No es código para copiar: es un vocabulario común para diseñar. El catálogo clásico viene del libro Design Patterns (1994) de Gamma, Helm, Johnson y Vlissides, la “Gang of Four”.

Creacionales (5)

Cómo se crean los objetos sin acoplar al cliente con tipos concretos.

Estructurales (7)

Cómo se componen objetos y tipos para formar estructuras mayores.

De comportamiento (10)

Cómo se reparten responsabilidades y se comunican los objetos (en Go VI).

Patrones en Go: muchos patrones se simplifican porque Go tiene funciones de primera clase, interfaces implícitas, embedding y canales. Un Strategy puede ser un map[string]func(...); un Singleton, una variable de paquete con sync.Once. Para profundizar, consulta el catálogo de Refactoring.Guru, que tiene una explicación ilustrada de cada patrón y ejemplos en Go.

3. Factory Method

Creacional ejemplos/patrones/factory-method Catálogo de referencia

Intención

Delegar en una función o método la decisión de qué tipo concreto crear, devolviendo una abstracción.

Problema en ZeldaInterpreter

El REPL debe imprimir resultados en texto plano, JSON o en un recuadro según una opción, sin llenar el código de if.

Úsalo cuando…

Cuando el cliente no debe conocer los tipos concretos o cuando la elección depende de configuración.

Evítalo si…

Si solo existe un tipo concreto: un constructor NewX basta.

En Go: En Go suele ser una función NewX(...) (Interfaz, error), sin jerarquías de creadores.
En el intérprete: lexer.New, parser.New y object.NewEnvironment son fábricas simples; NewPrinter(format) lo sería con varios formatos.
ejemplos/patrones/factory-method/main.go
// Factory Method: una función decide qué tipo concreto crear y devuelve una interfaz.
// Ejemplo: el REPL elige cómo imprimir resultados según una opción de línea de comandos.
package main

import (
	"fmt"
	"strings"
)

type Printer interface{ Print(result string) string }

type plainPrinter struct{}
type jsonPrinter struct{}
type boxPrinter struct{ width int }

func (plainPrinter) Print(r string) string { return r }
func (jsonPrinter) Print(r string) string  { return fmt.Sprintf(`{"result": %q}`, r) }
func (b boxPrinter) Print(r string) string {
	line := strings.Repeat("-", b.width)
	return fmt.Sprintf("+%s+\n|%-*s|\n+%s+", line, b.width, r, line)
}

// NewPrinter es el método fábrica: el cliente pide por nombre y recibe la abstracción.
func NewPrinter(format string) (Printer, error) {
	switch format {
	case "plain":
		return plainPrinter{}, nil
	case "json":
		return jsonPrinter{}, nil
	case "box":
		return boxPrinter{width: 8}, nil
	}
	return nil, fmt.Errorf("formato desconocido: %s", format)
}

func main() {
	for _, f := range []string{"plain", "json", "box", "xml"} {
		p, err := NewPrinter(f)
		if err != nil {
			fmt.Println("error:", err)
			continue
		}
		fmt.Println(p.Print("42"))
	}
}
$ go run ./patrones/factory-method
42
{"result": "42"}
+--------+
|42      |
+--------+
error: formato desconocido: xml

4. Abstract Factory

Creacional ejemplos/patrones/abstract-factory Catálogo de referencia

Intención

Crear familias completas de objetos relacionados que están diseñados para usarse juntos.

Problema en ZeldaInterpreter

El REPL tiene prompt y formato de errores; con colores ANSI o sin ellos. Mezclar un prompt con color y errores sin color sería inconsistente.

Úsalo cuando…

Cuando hay varias familias intercambiables (temas, plataformas, backends) y hay que garantizar coherencia.

Evítalo si…

Si solo hay un producto por familia: un Factory Method es suficiente.

En Go: Una interfaz con varios métodos NewX(); cada familia es un struct vacío que la implementa.
En el intérprete: Un Theme del REPL que produce Prompt y ErrorFormatter coherentes entre sí.
ejemplos/patrones/abstract-factory/main.go
// Abstract Factory: crear FAMILIAS de objetos relacionados que deben usarse juntos.
// Ejemplo: el tema del REPL (prompt + formato de errores) en versión "color" o "plana".
package main

import "fmt"

type Prompt interface{ Render() string }
type ErrorFormatter interface{ Format(msg string) string }

// Theme es la fábrica abstracta.
type Theme interface {
	NewPrompt() Prompt
	NewErrorFormatter() ErrorFormatter
}

// Familia "color" (secuencias ANSI de terminal)
type colorTheme struct{}
type colorPrompt struct{}
type colorErrors struct{}

func (colorTheme) NewPrompt() Prompt                 { return colorPrompt{} }
func (colorTheme) NewErrorFormatter() ErrorFormatter { return colorErrors{} }
func (colorPrompt) Render() string                   { return "\033[36m>>\033[0m " }
func (colorErrors) Format(m string) string           { return "\033[31merror:\033[0m " + m }

// Familia "plana" (archivos de log, terminales sin color)
type plainTheme struct{}
type plainPrompt struct{}
type plainErrors struct{}

func (plainTheme) NewPrompt() Prompt                 { return plainPrompt{} }
func (plainTheme) NewErrorFormatter() ErrorFormatter { return plainErrors{} }
func (plainPrompt) Render() string                   { return ">> " }
func (plainErrors) Format(m string) string           { return "[ERROR] " + m }

// El cliente solo conoce interfaces: nunca mezcla piezas de familias distintas.
func session(t Theme) {
	p, e := t.NewPrompt(), t.NewErrorFormatter()
	fmt.Printf("%q\n", p.Render()+"let x = ;")
	fmt.Printf("%q\n", e.Format("no prefix parse function for ; found"))
}

func main() {
	session(plainTheme{})
	session(colorTheme{})
}

">> let x = ;"
"[ERROR] no prefix parse function for ; found"
"\x1b[36m>>\x1b[0m let x = ;"
"\x1b[31merror:\x1b[0m no prefix parse function for ; found"

5. Builder

Creacional ejemplos/patrones/builder Catálogo de referencia

Intención

Construir un objeto complejo paso a paso, separando la construcción de su representación final.

Problema en ZeldaInterpreter

Las pruebas del parser necesitan programas y ASTs de ejemplo; armarlos con structs anidados es largo y frágil.

Úsalo cuando…

Objetos con muchas partes opcionales, validación al final o construcción en varios pasos.

Evítalo si…

Objetos simples con dos o tres campos: un literal de struct es más claro.

En Go: API fluida que devuelve *Builder; alternativa idiomática: functional options (New(WithTrace(true))).
En el intérprete: Un ProgramBuilder para tests y strings.Builder/bytes.Buffer en todos los String() del AST.
ejemplos/patrones/builder/main.go
// Builder: construir un objeto complejo paso a paso.
// Ejemplo: armar programas/AST de prueba con una API fluida en los tests del parser.
package main

import (
	"errors"
	"fmt"
	"strings"
)

type Program struct{ Statements []string }

func (p Program) String() string { return strings.Join(p.Statements, "\n") }

type ProgramBuilder struct {
	stmts []string
	err   error
}

func NewProgram() *ProgramBuilder { return &ProgramBuilder{} }

func (b *ProgramBuilder) Let(name, value string) *ProgramBuilder {
	if name == "" {
		b.err = errors.New("let sin nombre")
		return b
	}
	b.stmts = append(b.stmts, fmt.Sprintf("let %s = %s;", name, value))
	return b
}

func (b *ProgramBuilder) Return(value string) *ProgramBuilder {
	b.stmts = append(b.stmts, fmt.Sprintf("return %s;", value))
	return b
}

// Build valida y entrega el producto terminado.
func (b *ProgramBuilder) Build() (Program, error) {
	if b.err != nil {
		return Program{}, b.err
	}
	return Program{Statements: b.stmts}, nil
}

func main() {
	p, err := NewProgram().Let("x", "5").Let("y", "x * 2").Return("y").Build()
	fmt.Println(p)
	fmt.Println("err:", err)

	_, err = NewProgram().Let("", "1").Return("1").Build()
	fmt.Println("err:", err)
}
$ go run ./patrones/builder
let x = 5;
let y = x * 2;
return y;
err: <nil>
err: let sin nombre

6. Prototype

Creacional ejemplos/patrones/prototype Catálogo de referencia

Intención

Crear nuevos objetos clonando uno existente en lugar de construirlos desde cero.

Problema en ZeldaInterpreter

push de Monkey no debe modificar el array original: necesita una copia del array antes de agregar.

Úsalo cuando…

Cuando copiar es más simple que reconstruir, o cuando se necesitan copias independientes de estructuras anidadas.

Evítalo si…

Si los objetos son inmutables: se pueden compartir sin copiar.

En Go: Un método Clone() T; cuidado con la diferencia entre copia superficial y profunda de slices y maps.
En el intérprete: push y rest del Cap. 4 crean arrays nuevos; un método Clone() generaliza la idea.
ejemplos/patrones/prototype/main.go
// Prototype: crear objetos copiando (clonando) uno existente.
// Ejemplo: push en Monkey no modifica el array original: clona y luego agrega.
package main

import "fmt"

type Object interface {
	Inspect() string
	Clone() Object
}

type Integer struct{ Value int64 }

func (i *Integer) Inspect() string { return fmt.Sprint(i.Value) }
func (i *Integer) Clone() Object {
	c := *i
	return &c
}

type Array struct{ Elements []Object }

func (a *Array) Inspect() string { return fmt.Sprintf("%d elementos", len(a.Elements)) }

// Clone hace una copia PROFUNDA: también clona cada elemento.
func (a *Array) Clone() Object {
	elems := make([]Object, len(a.Elements))
	for i, e := range a.Elements {
		elems[i] = e.Clone()
	}
	return &Array{Elements: elems}
}

func push(arr *Array, v Object) *Array {
	c := arr.Clone().(*Array) // el original queda intacto
	c.Elements = append(c.Elements, v)
	return c
}

func main() {
	original := &Array{Elements: []Object{&Integer{Value: 1}, &Integer{Value: 2}}}
	nuevo := push(original, &Integer{Value: 3})

	nuevo.Elements[0].(*Integer).Value = 99 // modificar la copia...
	fmt.Println("original:", original.Inspect(), "primero =", original.Elements[0].Inspect())
	fmt.Println("nuevo:   ", nuevo.Inspect(), "primero =", nuevo.Elements[0].Inspect())
}
$ go run ./patrones/prototype
original: 2 elementos primero = 1
nuevo:    3 elementos primero = 99

7. Singleton

Creacional ejemplos/patrones/singleton Catálogo de referencia

Intención

Garantizar que exista una única instancia de un tipo y ofrecer un punto de acceso global a ella.

Problema en ZeldaInterpreter

Crear un &Boolean{true} nuevo en cada comparación desperdicia memoria e impide comparar por puntero.

Úsalo cuando…

Valores únicos por naturaleza (TRUE, FALSE, NULL) o registros globales de solo lectura.

Evítalo si…

Para estado mutable compartido: dificulta las pruebas y oculta dependencias.

En Go: Variables de paquete o sync.Once para inicialización perezosa y segura entre goroutines.
En el intérprete: TRUE, FALSE y NULL del evaluador (Semana 6) y el mapa builtins (Semana 8).
ejemplos/patrones/singleton/main.go
// Singleton: una única instancia compartida. En Go: variables de paquete o sync.Once.
package main

import (
	"fmt"
	"sync"
)

type Boolean struct{ Value bool }

// Instancias únicas, como TRUE/FALSE/NULL en el evaluador del libro.
var (
	TRUE  = &Boolean{Value: true}
	FALSE = &Boolean{Value: false}
)

func nativeBool(b bool) *Boolean {
	if b {
		return TRUE
	}
	return FALSE
}

// Registro de built-ins creado de forma perezosa, una sola vez y seguro entre goroutines.
type Registry struct{ names []string }

var (
	registry *Registry
	once     sync.Once
)

func Builtins() *Registry {
	once.Do(func() {
		fmt.Println("(inicializando registro: esto se imprime una sola vez)")
		registry = &Registry{names: []string{"len", "first", "last", "rest", "push", "puts"}}
	})
	return registry
}

func main() {
	fmt.Println("mismo TRUE:", nativeBool(1 < 2) == nativeBool(3 > 0))

	var wg sync.WaitGroup
	for range 3 {
		wg.Add(1)
		go func() {
			defer wg.Done()
			_ = Builtins()
		}()
	}
	wg.Wait()
	fmt.Println("misma instancia:", Builtins() == Builtins(), Builtins().names)
}
$ go run ./patrones/singleton
mismo TRUE: true
(inicializando registro: esto se imprime una sola vez)
misma instancia: true [len first last rest push puts]

8. Adapter

Estructural ejemplos/patrones/adapter Catálogo de referencia

Intención

Convertir la interfaz de un tipo existente en otra que el cliente espera, sin modificar ninguno de los dos.

Problema en ZeldaInterpreter

El lexer lee de un string, pero queremos alimentarlo desde archivos, la red o stdin (io.Reader).

Úsalo cuando…

Integrar código de terceros o de la biblioteca estándar con interfaces propias.

Evítalo si…

Si puedes cambiar directamente una de las dos interfaces sin romper a nadie.

En Go: Un struct pequeño que envuelve al adaptado e implementa la interfaz destino.
En el intérprete: Un Source del lexer adaptado desde io.Reader; el REPL ya recibe io.Reader/io.Writer.
ejemplos/patrones/adapter/main.go
// Adapter: hacer que una interfaz existente encaje con la que espera nuestro código.
// Ejemplo: el lexer espera un Source; queremos alimentarlo desde cualquier io.Reader.
package main

import (
	"bufio"
	"fmt"
	"io"
	"strings"
)

// Source es la interfaz que conoce nuestro lexer.
type Source interface {
	NextChar() (byte, bool)
}

// stringSource es la implementación nativa.
type stringSource struct {
	s   string
	pos int
}

func (s *stringSource) NextChar() (byte, bool) {
	if s.pos >= len(s.s) {
		return 0, false
	}
	s.pos++
	return s.s[s.pos-1], true
}

// readerAdapter adapta un io.Reader (archivo, red, stdin) a Source.
type readerAdapter struct{ r *bufio.Reader }

func FromReader(r io.Reader) Source { return &readerAdapter{r: bufio.NewReader(r)} }

func (a *readerAdapter) NextChar() (byte, bool) {
	b, err := a.r.ReadByte()
	if err != nil {
		return 0, false
	}
	return b, true
}

// countLetters es el cliente: solo depende de Source.
func countLetters(src Source) int {
	n := 0
	for ch, ok := src.NextChar(); ok; ch, ok = src.NextChar() {
		if ch >= 'a' && ch <= 'z' {
			n++
		}
	}
	return n
}

func main() {
	fmt.Println(countLetters(&stringSource{s: "let x = 5;"}))
	fmt.Println(countLetters(FromReader(strings.NewReader("fn(a, b)"))))
}
$ go run ./patrones/adapter
4
4

9. Bridge

Estructural ejemplos/patrones/bridge Catálogo de referencia

Intención

Separar una abstracción de su implementación para que ambas puedan evolucionar de forma independiente.

Problema en ZeldaInterpreter

Los reportes de error tienen variantes (corto, detallado) y destinos (terminal, HTML). Combinarlos por herencia daría 2 × 2 tipos.

Úsalo cuando…

Cuando hay dos dimensiones de variación que se multiplican.

Evítalo si…

Si solo hay una dimensión: una interfaz simple es suficiente.

En Go: La abstracción guarda una interfaz (el “puente”) como campo; se refina con embedding.
En el intérprete: Un reporte de errores del parser que puede mostrarse en terminal o en la web del curso.
ejemplos/patrones/bridge/main.go
// Bridge: separar una abstracción de su implementación para que varíen por separado.
// Abstracción: QUÉ se reporta de un error.  Implementación: DÓNDE se muestra.
package main

import (
	"fmt"
	"html"
)

// Renderer es la implementación (el "puente").
type Renderer interface {
	Title(s string) string
	Body(s string) string
}

type terminal struct{}
type htmlOut struct{}

func (terminal) Title(s string) string { return "== " + s + " ==" }
func (terminal) Body(s string) string  { return "   " + s }
func (htmlOut) Title(s string) string  { return "<h3>" + html.EscapeString(s) + "</h3>" }
func (htmlOut) Body(s string) string   { return "<p>" + html.EscapeString(s) + "</p>" }

// ErrorReport es la abstracción: guarda una referencia a la implementación.
type ErrorReport struct {
	r   Renderer
	msg string
}

func (e ErrorReport) Short() string { return e.r.Title("Error") + "\n" + e.r.Body(e.msg) }

// DetailedReport refina la abstracción sin tocar los renderers.
type DetailedReport struct {
	ErrorReport
	line, col int
}

func (d DetailedReport) Full() string {
	return d.Short() + "\n" + d.r.Body(fmt.Sprintf("línea %d, columna %d", d.line, d.col))
}

func main() {
	for _, r := range []Renderer{terminal{}, htmlOut{}} {
		rep := DetailedReport{ErrorReport: ErrorReport{r: r, msg: "expected =, got <INT>"}, line: 3, col: 7}
		fmt.Println(rep.Full())
	}
}
$ go run ./patrones/bridge

   expected =, got <INT>
   línea 3, columna 7
<h3>Error</h3>
<p>expected =, got &lt;INT&gt;</p>
<p>línea 3, columna 7</p>

10. Composite

Estructural ejemplos/patrones/composite Catálogo de referencia

Intención

Componer objetos en estructuras de árbol y tratar igual a las hojas y a los compuestos.

Problema en ZeldaInterpreter

Un programa tiene sentencias que contienen expresiones que contienen otras expresiones; queremos recorrer todo de forma uniforme.

Úsalo cuando…

Cualquier estructura jerárquica: ASTs, sistemas de archivos, menús, escenas gráficas.

Evítalo si…

Si los elementos no forman realmente una jerarquía.

En Go: Una interfaz común (Node) implementada por hojas y por nodos que guardan slices de Node.
En el intérprete: ¡El AST completo! Program y BlockStatement contienen Statements; InfixExpression contiene Expressions.
ejemplos/patrones/composite/main.go
// Composite: tratar igual a objetos individuales y a composiciones de objetos.
// ¡El AST es un Composite! Un bloque contiene sentencias que contienen expresiones.
package main

import (
	"fmt"
	"strings"
)

type Node interface {
	String() string
	Count() int // cuántos nodos tiene este subárbol
}

// Hojas
type Integer struct{ Value int }
type Ident struct{ Name string }

func (i Integer) String() string { return fmt.Sprint(i.Value) }
func (i Integer) Count() int     { return 1 }
func (i Ident) String() string   { return i.Name }
func (i Ident) Count() int       { return 1 }

// Compuestos
type Infix struct {
	Left  Node
	Op    string
	Right Node
}

func (n Infix) String() string {
	return "(" + n.Left.String() + " " + n.Op + " " + n.Right.String() + ")"
}
func (n Infix) Count() int { return 1 + n.Left.Count() + n.Right.Count() }

type Block struct{ Stmts []Node }

func (b Block) String() string {
	parts := make([]string, len(b.Stmts))
	for i, s := range b.Stmts {
		parts[i] = s.String()
	}
	return "{ " + strings.Join(parts, "; ") + " }"
}

func (b Block) Count() int {
	total := 1
	for _, s := range b.Stmts {
		total += s.Count() // no importa si s es hoja o compuesto
	}
	return total
}

func main() {
	tree := Block{Stmts: []Node{
		Infix{Left: Integer{1}, Op: "+", Right: Infix{Left: Integer{2}, Op: "*", Right: Ident{"x"}}},
		Ident{"y"},
	}}
	fmt.Println(tree, "->", tree.Count(), "nodos")
}
$ go run ./patrones/composite
{ (1 + (2 * x)); y } -> 7 nodos

11. Decorator

Estructural ejemplos/patrones/decorator Catálogo de referencia

Intención

Agregar responsabilidades a un objeto envolviéndolo en otro que implementa la misma interfaz.

Problema en ZeldaInterpreter

Queremos trazar o cronometrar el evaluador sin tocar su código ni crear subclases.

Úsalo cuando…

Funcionalidad opcional y combinable: logs, métricas, caché, reintentos, autorización.

Evítalo si…

Si el orden de las capas genera confusión o se apilan demasiadas.

En Go: Un struct con un campo inner Interfaz; el patrón de middleware HTTP es el mismo.
En el intérprete: El tracing del parser (trace/untrace) envuelto como decorador de Eval.
ejemplos/patrones/decorator/main.go
// Decorator: agregar responsabilidades envolviendo un objeto, sin modificar su código.
// Ejemplo: agregar traza y medición de tiempo a un evaluador.
package main

import (
	"fmt"
	"strings"
	"time"
)

type Evaluator interface {
	Eval(expr string) (int, error)
}

// Componente base: suma enteros "a + b + c".
type sumEvaluator struct{}

func (sumEvaluator) Eval(expr string) (int, error) {
	total := 0
	for _, p := range strings.Split(expr, "+") {
		var n int
		if _, err := fmt.Sscan(strings.TrimSpace(p), &n); err != nil {
			return 0, fmt.Errorf("no es entero: %q", strings.TrimSpace(p))
		}
		total += n
	}
	return total, nil
}

// Decorador 1: traza cada llamada.
type tracing struct{ inner Evaluator }

func (t tracing) Eval(expr string) (int, error) {
	fmt.Printf("-> Eval(%q)\n", expr)
	v, err := t.inner.Eval(expr)
	fmt.Printf("<- %d, err=%v\n", v, err)
	return v, err
}

// Decorador 2: mide el tiempo.
type timing struct{ inner Evaluator }

func (t timing) Eval(expr string) (int, error) {
	start := time.Now()
	defer func() { fmt.Println("   (medido:", time.Since(start) >= 0, ")") }()
	return t.inner.Eval(expr)
}

func main() {
	// Los decoradores se apilan como capas: tracing(timing(base)).
	var ev Evaluator = tracing{inner: timing{inner: sumEvaluator{}}}
	ev.Eval("1 + 2 + 3")
	ev.Eval("1 + x")
}
$ go run ./patrones/decorator
-> Eval("1 + 2 + 3")
   (medido: true )
<- 6, err=<nil>
-> Eval("1 + x")
   (medido: true )
<- 0, err=no es entero: "x"

12. Facade

Estructural ejemplos/patrones/facade Catálogo de referencia

Intención

Ofrecer una interfaz simple a un subsistema complejo.

Problema en ZeldaInterpreter

Ejecutar Monkey requiere crear lexer, parser, entorno, evaluar y revisar errores: demasiados pasos para quien solo quiere un resultado.

Úsalo cuando…

Para dar un punto de entrada sencillo a una librería o a un conjunto de paquetes.

Evítalo si…

Si la fachada empieza a crecer sin control y se vuelve un “objeto dios”.

En Go: Un struct o función de alto nivel que coordina los paquetes internos.
En el intérprete: Una función zelda.Run(src) (string, error) para incrustar el intérprete en otras aplicaciones.
ejemplos/patrones/facade/main.go
// Facade: una interfaz simple frente a un subsistema complejo.
// Ejemplo: Interpreter.Run esconde lexer, parser y evaluador detrás de un solo método.
package main

import (
	"fmt"
	"strconv"
	"strings"
)

// --- Subsistema (muy simplificado) ---
type lexer struct{}
type parser struct{}
type evaluator struct{ env map[string]int }

func (lexer) Tokens(src string) []string { return strings.Fields(src) }

func (parser) ParseLet(toks []string) (name, value string, err error) {
	if len(toks) != 4 || toks[0] != "let" || toks[2] != "=" {
		return "", "", fmt.Errorf("se esperaba: let <nombre> = <valor>")
	}
	return toks[1], toks[3], nil
}

func (e *evaluator) Bind(name, value string) (int, error) {
	n, err := strconv.Atoi(value)
	if err != nil {
		v, ok := e.env[value]
		if !ok {
			return 0, fmt.Errorf("identifier not found: %s", value)
		}
		n = v
	}
	e.env[name] = n
	return n, nil
}

// --- Fachada ---
type Interpreter struct {
	l lexer
	p parser
	e *evaluator
}

func New() *Interpreter { return &Interpreter{e: &evaluator{env: map[string]int{}}} }

func (in *Interpreter) Run(src string) (string, error) {
	name, value, err := in.p.ParseLet(in.l.Tokens(src))
	if err != nil {
		return "", err
	}
	n, err := in.e.Bind(name, value)
	if err != nil {
		return "", err
	}
	return fmt.Sprintf("%s = %d", name, n), nil
}

func main() {
	z := New() // el cliente solo conoce New y Run
	for _, src := range []string{"let x = 5", "let y = x", "let z = w", "x + 1"} {
		out, err := z.Run(src)
		if err != nil {
			fmt.Printf("%-10s -> error: %v\n", src, err)
			continue
		}
		fmt.Printf("%-10s -> %s\n", src, out)
	}
}
$ go run ./patrones/facade
let x = 5  -> x = 5
let y = x  -> y = 5
let z = w  -> error: identifier not found: w
x + 1      -> error: se esperaba: let <nombre> = <valor>

13. Flyweight

Estructural ejemplos/patrones/flyweight Catálogo de referencia

Intención

Compartir objetos inmutables en lugar de crear muchas copias idénticas.

Problema en ZeldaInterpreter

Un programa que itera mil veces crea miles de Integer con valores pequeños repetidos.

Úsalo cuando…

Cuando hay muchísimos objetos iguales e inmutables y la memoria importa.

Evítalo si…

Si los objetos son mutables: un cambio afectaría a todos los que los comparten.

En Go: Un slice o mapa de instancias precreadas y una función fábrica que las reutiliza.
En el intérprete: TRUE/FALSE/NULL ya son flyweights; un caché de enteros pequeños sería el siguiente paso.
ejemplos/patrones/flyweight/main.go
// Flyweight: compartir objetos inmutables cuando hay muchísimos iguales.
// Ejemplo: caché de enteros pequeños (como CPython) e "interning" de identificadores.
package main

import "fmt"

type Integer struct{ Value int64 } // debe tratarse como INMUTABLE

const minCached, maxCached = -5, 256

var smallInts = func() []*Integer {
	cache := make([]*Integer, maxCached-minCached+1)
	for i := range cache {
		cache[i] = &Integer{Value: int64(i + minCached)}
	}
	return cache
}()

// NewInteger devuelve una instancia compartida para valores pequeños.
func NewInteger(v int64) *Integer {
	if v >= minCached && v <= maxCached {
		return smallInts[v-minCached]
	}
	return &Integer{Value: v}
}

// Interner guarda un único string por nombre de identificador.
type Interner struct{ pool map[string]*string }

func (in *Interner) Intern(s string) *string {
	if p, ok := in.pool[s]; ok {
		return p
	}
	p := &s
	in.pool[s] = p
	return p
}

func main() {
	fmt.Println("7 compartido:   ", NewInteger(7) == NewInteger(7))
	fmt.Println("1000 compartido:", NewInteger(1000) == NewInteger(1000))

	in := &Interner{pool: map[string]*string{}}
	a, b := in.Intern("contador"), in.Intern("contador")
	fmt.Println("mismo string:", a == b, "| tamaño del pool:", len(in.pool))
}
$ go run ./patrones/flyweight
7 compartido:    true
1000 compartido: false
mismo string: true | tamaño del pool: 1

14. Proxy

Estructural ejemplos/patrones/proxy Catálogo de referencia

Intención

Proveer un sustituto que controla el acceso al objeto real (protección, caché, carga perezosa, registro).

Problema en ZeldaInterpreter

Queremos impedir que se reasignen constantes, o evitar recalcular resultados costosos.

Úsalo cuando…

Control de acceso, memoización, objetos remotos o costosos de crear.

Evítalo si…

Si solo agrega una indirección sin beneficio real.

En Go: Un struct que implementa la misma interfaz y delega en el objeto real.
En el intérprete: Un Environment de solo lectura para constantes o un caché de funciones puras.
ejemplos/patrones/proxy/main.go
// Proxy: un sustituto que controla el acceso al objeto real.
// Ejemplos: entorno con constantes protegidas y caché (memoización) de una función costosa.
package main

import (
	"errors"
	"fmt"
)

type Env interface {
	Get(name string) (int, bool)
	Set(name string, v int) error
}

type realEnv struct{ store map[string]int }

func (e *realEnv) Get(n string) (int, bool) {
	v, ok := e.store[n]
	return v, ok
}

func (e *realEnv) Set(n string, v int) error {
	e.store[n] = v
	return nil
}

// protectedEnv es un proxy de protección: impide reasignar constantes.
type protectedEnv struct {
	real   Env
	consts map[string]bool
}

func (p protectedEnv) Get(n string) (int, bool) { return p.real.Get(n) }
func (p protectedEnv) Set(n string, v int) error {
	if p.consts[n] {
		return errors.New("no se puede reasignar la constante " + n)
	}
	return p.real.Set(n, v)
}

// cachedFib es un proxy de caché: evita recalcular.
type cachedFib struct {
	calls int
	memo  map[int]int
}

func (c *cachedFib) Fib(n int) int {
	if v, ok := c.memo[n]; ok {
		return v
	}
	c.calls++
	v := n
	if n >= 2 {
		v = c.Fib(n-1) + c.Fib(n-2)
	}
	c.memo[n] = v
	return v
}

func main() {
	var env Env = protectedEnv{
		real:   &realEnv{store: map[string]int{"PI": 3}},
		consts: map[string]bool{"PI": true},
	}
	fmt.Println("Set x: ", env.Set("x", 1))
	fmt.Println("Set PI:", env.Set("PI", 4))

	f := &cachedFib{memo: map[int]int{}}
	fmt.Println("fib(40) =", f.Fib(40), "con", f.calls, "cálculos reales")
}
$ go run ./patrones/proxy
Set x:  <nil>
Set PI: no se puede reasignar la constante PI
fib(40) = 102334155 con 41 cálculos reales

Cuidado con la “patronitis”: un patrón agrega indirección. Úsalo cuando el problema que resuelve ya existe, no por si acaso. En Go, la solución más simple (una función, un map, una interfaz de un método) suele ser la correcta.

16. Ideas clave

Factory Method

Delegar en una función o método la decisión de qué tipo concreto crear, devolviendo una abstracción.

Abstract Factory

Crear familias completas de objetos relacionados que están diseñados para usarse juntos.

Builder

Construir un objeto complejo paso a paso, separando la construcción de su representación final.

Prototype

Crear nuevos objetos clonando uno existente en lugar de construirlos desde cero.

Singleton

Garantizar que exista una única instancia de un tipo y ofrecer un punto de acceso global a ella.

Adapter

Convertir la interfaz de un tipo existente en otra que el cliente espera, sin modificar ninguno de los dos.

Regla de oro en Go: empieza por lo más simple (funciones e interfaces pequeñas) y reconoce el patrón cuando aparezca; no al revés.
