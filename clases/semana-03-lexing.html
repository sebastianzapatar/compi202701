Análisis Léxico: Tokens, Lexer y REPL

Comenzamos oficialmente la construcción del intérprete de Monkey. Hoy transformaremos texto plano en una secuencia estructurada de tokens y pondremos a correr nuestro primer REPL interactivo.

Libro: Intro + Cap. 1 (pp. 5–27) Paquetes: token, lexer, repl, main.go Incluye simulador interactivo en vivo

1. ¿Qué es un Intérprete? (Tipos y Pipeline)

Un intérprete toma código fuente y lo evalúa directamente sin producir un ejecutable binario independiente. Pero no todos los intérpretes funcionan igual:

Tree-Walking (Nuestro enfoque)

Convierte el código en tokens, construye un AST y camina recursivamente por el árbol evaluando cada nodo.

Claro, didáctico y fácil de extender.

Bytecode VM

Compila el AST a instrucciones compactas (bytecode) que ejecuta una Máquina Virtual. Ej: Python (CPython), Lua, Ruby.

Mucho más rápido en ejecución.

JIT (Just-In-Time)

Traduce partes calientes del código a código máquina nativo en tiempo de ejecución. Ej: V8 (JS), JVM, PyPy.

Rendimiento cercano a C.

2. ¿Qué hace exactamente el Análisis Léxico?

Trabajar directamente con texto plano es incómodo y propenso a errores. El Lexer (también llamado scanner o tokenizer) realiza la primera transformación: agrupa caracteres en piezas atómicas llamadas Tokens.

Entrada: Cadena de caracteres

Código fuente Monkey
let x = 5 + 5;

Para la computadora esto es solo una secuencia de bytes: 'l', 'e', 't', ' ', 'x', ' ', '=', ...

Salida: Flujo de Tokens

Secuencia de token.Token
{Type: LET,       Literal: "let"}
{Type: IDENT,     Literal: "x"}
{Type: ASSIGN,    Literal: "="}
{Type: INT,       Literal: "5"}
{Type: PLUS,      Literal: "+"}
{Type: INT,       Literal: "5"}
{Type: SEMICOLON, Literal: ";"}
{Type: EOF,       Literal: ""}
Responsabilidad estricta del Lexer: El Lexer NO verifica si el código tiene sentido (si falta un ; o si alguien escribió !-/*5;). Su único trabajo es producir tokens válidos o ILLEGAL si encuentra un símbolo desconocido. La gramática le corresponde al Parser.

3. Definiendo los Tokens (token/token.go)

Cada Token tiene dos campos: un Type (para categorizarlo) y un Literal (el texto original, para no perder si un INT era 5 o 10).

token/token.go
package token

type TokenType string

type Token struct {
    Type    TokenType
    Literal string
}

const (
    ILLEGAL = "ILLEGAL"
    EOF     = "EOF"

    // Identificadores y literales
    IDENT = "IDENT" // add, foobar, x, y...
    INT   = "INT"   // 1343456

    // Operadores
    ASSIGN   = "="
    PLUS     = "+"
    MINUS    = "-"
    BANG     = "!"
    ASTERISK = "*"
    SLASH    = "/"
    LT       = "<"
    GT       = ">"
    EQ       = "=="
    NOT_EQ   = "!="

    // Delimitadores
    COMMA     = ","
    SEMICOLON = ";"
    LPAREN    = "("
    RPAREN    = ")"
    LBRACE    = "{"
    RBRACE    = "}"

    // Palabras reservadas (Keywords)
    FUNCTION = "FUNCTION"
    LET      = "LET"
    TRUE     = "TRUE"
    FALSE    = "FALSE"
    IF       = "IF"
    ELSE     = "ELSE"
    RETURN   = "RETURN"
)
token/token.go · LookupIdent
var keywords = map[string]TokenType{
    "fn":     FUNCTION,
    "let":    LET,
    "true":   TRUE,
    "false":  FALSE,
    "if":     IF,
    "else":   ELSE,
    "return": RETURN,
}

func LookupIdent(ident string) TokenType {
    if tok, ok := keywords[ident]; ok {
        return tok
    }
    return IDENT
}

¿Por qué TokenType es string?

Usar int o byte sería ligeramente más rápido, pero usar string hace que depurar y leer fallos de tests sea inmediato sin tablas de traducción.

4. Arquitectura Interna del Lexer (Doble Puntero)

El Lexer mantiene 4 campos para recorrer el string input de izquierda a derecha sin perder nunca la capacidad de "espiar" el carácter siguiente:

0l
1e
2t
3␣
4xposition (ch='x')
5␣readPosition
6=
7␣
85
9;
lexer/lexer.go · Estructura y readChar
package lexer

import "monkey/token"

type Lexer struct {
    input        string
    position     int  // posición actual (apunta a ch)
    readPosition int  // siguiente posición a leer
    ch           byte // carácter actual bajo examen
}

func New(input string) *Lexer {
    l := &Lexer{input: input}
    l.readChar() // inicializa ch, position y readPosition
    return l
}

func (l *Lexer) readChar() {
    if l.readPosition >= len(l.input) {
        l.ch = 0 // código ASCII NUL -> fin de entrada (EOF)
    } else {
        l.ch = l.input[l.readPosition]
    }
    l.position = l.readPosition
    l.readPosition += 1
}

¿Por qué necesitamos DOS índices?

  • position señala el byte actual almacenado en ch (útil como inicio al hacer slicing l.input[pos:l.position]).
  • readPosition siempre está 1 paso adelante, listo para leer el siguiente carácter o espiarlo con peekChar().
  • Cuando llegamos al final del string, l.ch = 0 (ASCII NUL), lo que dispara limpiamente token.EOF.
Nota sobre Unicode: Monkey usa byte (ASCII) por simplicidad pedagógica. Soportar UTF-8 completo requeriría usar rune y leer anchos variables.

5. NextToken(), Espacios, Palabras y Números

Cada vez que el Parser necesita el siguiente token, llama a l.NextToken(). Primero ignoramos espacios en blanco y luego examinamos l.ch con un switch:

lexer/lexer.go · NextToken
func (l *Lexer) NextToken() token.Token {
    var tok token.Token

    l.skipWhitespace()

    switch l.ch {
    case '+':
        tok = newToken(token.PLUS, l.ch)
    case '-':
        tok = newToken(token.MINUS, l.ch)
    case '/':
        tok = newToken(token.SLASH, l.ch)
    case '*':
        tok = newToken(token.ASTERISK, l.ch)
    case '<':
        tok = newToken(token.LT, l.ch)
    case '>':
        tok = newToken(token.GT, l.ch)
    case ';':
        tok = newToken(token.SEMICOLON, l.ch)
    case ',':
        tok = newToken(token.COMMA, l.ch)
    case '(':
        tok = newToken(token.LPAREN, l.ch)
    case ')':
        tok = newToken(token.RPAREN, l.ch)
    case '{':
        tok = newToken(token.LBRACE, l.ch)
    case '}':
        tok = newToken(token.RBRACE, l.ch)
    case 0:
        tok.Literal = ""
        tok.Type = token.EOF
    default:
        if isLetter(l.ch) {
            tok.Literal = l.readIdentifier()
            tok.Type = token.LookupIdent(tok.Literal)
            return tok // ¡RETURN TEMPRANO!
        } else if isDigit(l.ch) {
            tok.Type = token.INT
            tok.Literal = l.readNumber()
            return tok // ¡RETURN TEMPRANO!
        } else {
            tok = newToken(token.ILLEGAL, l.ch)
        }
    }

    l.readChar()
    return tok
}
Helpers de lectura
func (l *Lexer) skipWhitespace() {
    for l.ch == ' ' || l.ch == '\t' ||
        l.ch == '\n' || l.ch == '\r' {
        l.readChar()
    }
}

func (l *Lexer) readIdentifier() string {
    position := l.position
    for isLetter(l.ch) {
        l.readChar()
    }
    return l.input[position:l.position]
}

func (l *Lexer) readNumber() string {
    position := l.position
    for isDigit(l.ch) {
        l.readChar()
    }
    return l.input[position:l.position]
}

func isLetter(ch byte) bool {
    return 'a' <= ch && ch <= 'z' ||
           'A' <= ch && ch <= 'Z' || ch == '_'
}

func isDigit(ch byte) bool {
    return '0' <= ch && ch <= '9'
}
Bug clásico de examen: ¿Por qué isLetter y isDigit hacen return tok antes del final? Porque readIdentifier() ya avanzó l.ch al primer carácter no-letra. Si dejáramos correr el l.readChar() del final, ¡nos saltaríamos un carácter (por ejemplo el ;)!

6. Tokens de Dos Caracteres: == y != con peekChar()

¿Cómo distingue el Lexer entre = (ASSIGN) y == (EQ), o entre ! (BANG) y != (NOT_EQ)? Espiando un carácter adelante sin avanzar.

lexer/lexer.go · peekChar()
func (l *Lexer) peekChar() byte {
    if l.readPosition >= len(l.input) {
        return 0
    } else {
        return l.input[l.readPosition]
    }
}
lexer/lexer.go · Casos '=' y '!'
case '=':
    if l.peekChar() == '=' {
        ch := l.ch          // guardamos el primer '='
        l.readChar()        // avanzamos al segundo '='
        literal := string(ch) + string(l.ch)
        tok = token.Token{Type: token.EQ, Literal: literal}
    } else {
        tok = newToken(token.ASSIGN, l.ch)
    }
case '!':
    if l.peekChar() == '=' {
        ch := l.ch
        l.readChar()
        literal := string(ch) + string(l.ch)
        tok = token.Token{Type: token.NOT_EQ, Literal: literal}
    } else {
        tok = newToken(token.BANG, l.ch)
    }
Lookahead de 1 carácter: Observa la elegancia de haber separado position y readPosition: peekChar() es casi idéntico a readChar(), pero no modifica los índices. Solo si confirmamos el segundo carácter ('=') consumimos con l.readChar().

7. Probando el Lexer con Table-Driven Tests

En lexer/lexer_test.go probamos código real de Monkey e incluso líneas sin sentido sintáctico como !-/*5; para ejercitar todos los tokens y casos borde:

lexer/lexer_test.go
package lexer

import (
    "testing"
    "monkey/token"
)

func TestNextToken(t *testing.T) {
    input := `let five = 5;
let ten = 10;

let add = fn(x, y) {
  x + y;
};

let result = add(five, ten);
!-/*5;
5 < 10 > 5;

if (5 < 10) {
    return true;
} else {
    return false;
}

10 == 10;
10 != 9;
`
    tests := []struct {
        expectedType    token.TokenType
        expectedLiteral string
    }{
        {token.LET, "let"},
        {token.IDENT, "five"},
        {token.ASSIGN, "="},
        {token.INT, "5"},
        {token.SEMICOLON, ";"},
        // ... resto de tokens hasta token.EOF
    }

    l := New(input)

    for i, tt := range tests {
        tok := l.NextToken()
        if tok.Type != tt.expectedType {
            t.Fatalf("tests[%d] - tokentype wrong. expected=%q, got=%q",
                i, tt.expectedType, tok.Type)
        }
        if tok.Literal != tt.expectedLiteral {
            t.Fatalf("tests[%d] - literal wrong. expected=%q, got=%q",
                i, tt.expectedLiteral, tok.Literal)
        }
    }
}

8. Nuestro Primer REPL (repl/repl.go y main.go)

REPL significa Read - Eval - Print - Loop. Aún no evaluamos código, pero ya podemos leer líneas del usuario y mostrar en tiempo real todos los tokens que reconoce nuestro Lexer:

repl/repl.go
package repl

import (
    "bufio"
    "fmt"
    "io"
    "monkey/lexer"
    "monkey/token"
)

const PROMPT = ">> "

func Start(in io.Reader, out io.Writer) {
    scanner := bufio.NewScanner(in)

    for {
        fmt.Fprintf(out, PROMPT)
        scanned := scanner.Scan()
        if !scanned {
            return
        }

        line := scanner.Text()
        l := lexer.New(line)

        for tok := l.NextToken(); tok.Type != token.EOF; tok = l.NextToken() {
            fmt.Fprintf(out, "%+v\n", tok)
        }
    }
}
main.go
package main

import (
    "fmt"
    "os"
    "os/user"
    "monkey/repl"
)

func main() {
    user, err := user.Current()
    if err != nil {
        panic(err)
    }
    fmt.Printf("Hello %s! This is the Monkey programming language!\n",
        user.Username)
    fmt.Printf("Feel free to type in commands\n")
    repl.Start(os.Stdin, os.Stdout)
}
