Análisis Sintáctico I: AST y Sentencias

El Lexer nos entrega una lista plana de tokens. Hoy construimos la estructura que les da forma: el Árbol de Sintaxis Abstracta y un parser recursivo descendente capaz de reconocer sentencias let y return.

1. ¿Qué es un Parser?

Un parser toma datos de entrada (normalmente texto o tokens) y construye una estructura de datos jerárquica que los representa, verificando la sintaxis en el proceso. Ya usaste uno sin notarlo:

JavaScript · JSON.parse
> var input = '{"name": "Thorsten", "age": 28}';
> var output = JSON.parse(input);
> output.name
'Thorsten'
> output.age
28

Texto → estructura

La entrada es solo un string. La salida es un objeto con campos navegables. Un parser de un lenguaje de programación hace lo mismo, pero la estructura resultante es un árbol.

En Monkey: tokens → *ast.Program.

¿Por qué “abstracto”?

Detalles como el punto y coma, los saltos de línea, los comentarios o los paréntesis guían al parser, pero no se guardan en el árbol. El AST conserva solo lo que importa para evaluar el programa.

  • IfExpression
    • Infix>
      • Infix*
        • Integer3
        • Integer5
      • Integer10
    • Returnconsequence
      • String"hello"
    • Returnalternative
      • String"goodbye"

AST de if (3 * 5 > 10) { return "hello"; } else { return "goodbye"; } — los paréntesis y llaves ya no aparecen.

2. ¿Por qué no usar un generador de parsers?

Herramientas como yacc, bison o ANTLR reciben una gramática formal (usualmente una gramática libre de contexto escrita en BNF/EBNF) y generan el código del parser automáticamente.

Generadores de parsers

  • Muy usados en producción y bien probados.
  • Escribes la gramática, no el algoritmo.
  • Pero esconden cómo funciona el parsing.
EBNF (fragmento de ECMAScript)
PrimaryExpression ::= "this"
                    | ObjectLiteral
                    | ( "(" Expression ")" )
                    | Identifier
                    | ArrayLiteral
                    | Literal

Parser escrito a mano (nuestra ruta)

  • El objetivo del curso es entender, no solo usar.
  • Muchos parsers reales se escriben a mano (Go, GCC, Clang, V8).
  • Escribiremos un parser recursivo descendente (top-down).
  • Para expresiones: Pratt parser (Top Down Operator Precedence), la próxima semana.
Top-down vs bottom-up: un parser top-down empieza construyendo el nodo raíz y desciende hacia las hojas. Un parser bottom-up (como los LR que generan yacc/bison) hace lo contrario. El recursivo descendente es el más intuitivo porque refleja directamente cómo pensamos la gramática.

3. Sentencias vs Expresiones en Monkey

Sentencias (statements)

No producen un valor. Monkey tiene solo dos: let y return.

let x = 5;
return 10;

Expresiones (expressions)

Sí producen un valor. En Monkey casi todo es una expresión, ¡incluso las funciones!

5
add(5, 5)
fn(x, y) { x + y }

Anatomía de una sentencia let

Forma general
let <identificador> = <expresión>;

Necesitamos un nodo con tres piezas: el token let, el nombre (un identificador) y el valor (una expresión). Así se ve let x = 5; dentro del programa:

  • *ast.ProgramStatements[0]
    • *ast.LetStatementToken: LET
      • Name: *ast.Identifier"x"
      • Value: ast.Expression5
Pregunta para la clase: ¿por qué el identificador x en let x = 5; se modela como *ast.Identifier (una expresión) si allí no produce ningún valor? Respuesta del libro: por simplicidad — en otras partes del programa (let y = x;) el mismo identificador sí produce un valor, y así reutilizamos un solo tipo de nodo.

4. El paquete ast: interfaces base

Todo nodo del árbol implementa Node. Los nodos se dividen en dos familias que separamos con métodos “marcadores” vacíos para que el compilador de Go nos avise si usamos uno donde va el otro.

ast/ast.go
package ast

import "monkey/token"

type Node interface {
    TokenLiteral() string
}

type Statement interface {
    Node
    statementNode()
}

type Expression interface {
    Node
    expressionNode()
}
ast/ast.go — nodo raíz
type Program struct {
    Statements []Statement
}

func (p *Program) TokenLiteral() string {
    if len(p.Statements) > 0 {
        return p.Statements[0].TokenLiteral()
    } else {
        return ""
    }
}
PiezaPara qué sirve
TokenLiteral()Devuelve el literal del token asociado al nodo. Solo se usa para depurar y en las pruebas.
statementNode() / expressionNode()Métodos vacíos “marca”: hacen que Statement y Expression sean interfaces distintas.
ProgramRaíz de todo AST. Un programa Monkey válido es una serie de sentencias.

5. Nodos LetStatement e Identifier

ast/ast.go
type LetStatement struct {
    Token token.Token // el token token.LET
    Name  *Identifier
    Value Expression
}

func (ls *LetStatement) statementNode()       {}
func (ls *LetStatement) TokenLiteral() string { return ls.Token.Literal }

type Identifier struct {
    Token token.Token // el token token.IDENT
    Value string
}

func (i *Identifier) expressionNode()      {}
func (i *Identifier) TokenLiteral() string { return i.Token.Literal }
Conexión con la Semana 2: aquí usamos exactamente los patrones que practicamos: structs con punteros a otros nodos, interfaces implícitas (nadie escribe “implements”) y métodos con pointer receiver.

6. El struct Parser: una ventana de dos tokens

El parser se parece mucho al Lexer: en vez de position/readPosition sobre caracteres, mantiene curToken y peekToken sobre tokens.

parser/parser.go
package parser

import (
    "monkey/ast"
    "monkey/lexer"
    "monkey/token"
)

type Parser struct {
    l *lexer.Lexer

    curToken  token.Token
    peekToken token.Token
}

func New(l *lexer.Lexer) *Parser {
    p := &Parser{l: l}

    // Lee dos tokens para que curToken
    // y peekToken queden inicializados
    p.nextToken()
    p.nextToken()

    return p
}

func (p *Parser) nextToken() {
    p.curToken = p.peekToken
    p.peekToken = p.l.NextToken()
}

¿Por qué necesitamos peekToken?

Con curToken sabemos dónde estamos; con peekToken decidimos qué hacer después.

Ejemplo: si curToken es 5, ¿es un literal suelto o el inicio de 5 + 5? Solo el siguiente token lo dice.

Dos llamadas en New: la primera llena peekToken; la segunda desplaza ese valor a curToken y vuelve a llenar peekToken.

7. ParseProgram, parseLetStatement y expectPeek

parser/parser.go
func (p *Parser) ParseProgram() *ast.Program {
    program := &ast.Program{}
    program.Statements = []ast.Statement{}

    for p.curToken.Type != token.EOF {
        stmt := p.parseStatement()
        if stmt != nil {
            program.Statements = append(program.Statements, stmt)
        }
        p.nextToken()
    }
    return program
}

func (p *Parser) parseStatement() ast.Statement {
    switch p.curToken.Type {
    case token.LET:
        return p.parseLetStatement()
    default:
        return nil
    }
}
parser/parser.go
func (p *Parser) parseLetStatement() *ast.LetStatement {
    stmt := &ast.LetStatement{Token: p.curToken}

    if !p.expectPeek(token.IDENT) {
        return nil
    }
    stmt.Name = &ast.Identifier{Token: p.curToken, Value: p.curToken.Literal}

    if !p.expectPeek(token.ASSIGN) {
        return nil
    }
    // TODO: saltamos la expresión hasta
    // encontrar un punto y coma
    for !p.curTokenIs(token.SEMICOLON) {
        p.nextToken()
    }
    return stmt
}

func (p *Parser) curTokenIs(t token.TokenType) bool {
    return p.curToken.Type == t
}
func (p *Parser) peekTokenIs(t token.TokenType) bool {
    return p.peekToken.Type == t
}
func (p *Parser) expectPeek(t token.TokenType) bool {
    if p.peekTokenIs(t) {
        p.nextToken()
        return true
    } else {
        return false
    }
}
expectPeek es una “aserción”: solo avanza si el siguiente token es el esperado. Así se impone el orden correcto de los tokens — este es el corazón de un parser recursivo descendente. Fíjate también en el TODO: las expresiones las parsearemos en la Semana 5.

        if !testLetStatement(t, stmt, tt.expectedIdentifier) {

        }

parser/parser_test.go — helper
func testLetStatement(t *testing.T, s ast.Statement, name string) bool {
    if s.TokenLiteral() != "let" {
        t.Errorf("s.TokenLiteral not 'let'. got=%q", s.TokenLiteral())
        return false
    }

    letStmt, ok := s.(*ast.LetStatement)
    if !ok {
        t.Errorf("s not *ast.LetStatement. got=%T", s)
        return false
    }

    if letStmt.Name.Value != name {
        t.Errorf("letStmt.Name.Value not '%s'. got=%s",
            name, letStmt.Name.Value)
        return false
    }

    if letStmt.Name.TokenLiteral() != name {
        t.Errorf("letStmt.Name.TokenLiteral() not '%s'. got=%s",
            name, letStmt.Name.TokenLiteral())
        return false
    }
    return true
}
Observa la type assertion s.(*ast.LetStatement) que vimos en la Semana 2: convierte la interfaz ast.Statement a su tipo concreto y nos dice con ok si la conversión fue posible.

9. Errores útiles: errors, Errors() y peekError

Si alguien escribe let = 10; el parser no debe fallar en silencio. Agregamos un slice de mensajes y lo llenamos cada vez que expectPeek no encuentra lo esperado.

parser/parser.go
type Parser struct {
    l      *lexer.Lexer
    errors []string
    // [...]
}

func New(l *lexer.Lexer) *Parser {
    p := &Parser{
        l:      l,
        errors: []string{},
    }
    // [...]
}

func (p *Parser) Errors() []string {
    return p.errors
}

func (p *Parser) peekError(t token.TokenType) {
    msg := fmt.Sprintf("expected next token to be %s, got %s instead",
        t, p.peekToken.Type)
    p.errors = append(p.errors, msg)
}

func (p *Parser) expectPeek(t token.TokenType) bool {
    if p.peekTokenIs(t) {
        p.nextToken()
        return true
    } else {
        p.peekError(t)
        return false
    }
}
parser/parser_test.go
func checkParserErrors(t *testing.T, p *Parser) {
    errors := p.Errors()
    if len(errors) == 0 {
        return
    }

    t.Errorf("parser has %d errors", len(errors))
    for _, msg := range errors {
        t.Errorf("parser error: %q", msg)
    }
    t.FailNow()
}

10. Sentencias return

Forma: return <expresión>;. Es más sencilla que let: solo hay un token fijo y luego una expresión.

ast/ast.go
type ReturnStatement struct {
    Token       token.Token // el token 'return'
    ReturnValue Expression
}

func (rs *ReturnStatement) statementNode()       {}
func (rs *ReturnStatement) TokenLiteral() string { return rs.Token.Literal }
parser/parser.go
func (p *Parser) parseStatement() ast.Statement {
    switch p.curToken.Type {
    case token.LET:
        return p.parseLetStatement()
    case token.RETURN:
        return p.parseReturnStatement()
    default:
        return nil
    }
}

func (p *Parser) parseReturnStatement() *ast.ReturnStatement {
    stmt := &ast.ReturnStatement{Token: p.curToken}

    p.nextToken()

    // TODO: saltamos la expresión hasta el ;
    for !p.curTokenIs(token.SEMICOLON) {
        p.nextToken()
    }
    return stmt
}
parser/parser_test.go
func TestReturnStatements(t *testing.T) {
    input := `
return 5;
return 10;
return 993322;
`
    l := lexer.New(input)
    p := New(l)
    program := p.ParseProgram()
    checkParserErrors(t, p)

    if len(program.Statements) != 3 {
        t.Fatalf("program.Statements does not contain 3 statements. got=%d", len(program.Statements))
    }
    for _, stmt := range program.Statements {
        returnStmt, ok := stmt.(*ast.ReturnStatement)
        if !ok {
            t.Errorf("stmt not *ast.ReturnStatement. got=%T", stmt)
            continue
        }
        if returnStmt.TokenLiteral() != "return" {
            t.Errorf("returnStmt.TokenLiteral not 'return', got %q", returnStmt.TokenLiteral())
        }
    }
}

12. Ideas clave de la semana

El AST es abstracto

Guarda la estructura, no la sintaxis superficial (;, paréntesis, espacios).

Dos familias de nodos

Statement y Expression se distinguen con métodos marcadores vacíos.

Ventana de dos tokens

curToken + peekToken permiten decidir sin retroceder.

expectPeek impone el orden

Avanza solo si el siguiente token es el correcto; si no, registra un error.

Errores acumulados

El parser no se detiene en el primer error: los reúne en p.errors.

TDD siempre

Cada tipo de sentencia nace de una prueba que primero falla.
