Evaluación II: Entornos, Funciones y Closures

Nuestro intérprete ya calcula, pero no recuerda nada. Hoy le damos memoria con el Environment, convertimos las funciones en valores de primera clase y descubrimos que los closures salen casi gratis.

Libro: Cap. 3.9 – 3.11 (pp. 136–151) Archivos: object/environment.go, evaluator.go REPL con visor de entorno
1Implementar un Environment que asocia nombres con objetos.
2Representar funciones como objetos que capturan su entorno.
3Evaluar llamadas con entornos encerrados (outer).
4Explicar por qué funcionan los closures y quién libera la memoria.

1. Bindings y el Environment

Un binding asocia un nombre con un valor: let x = 5 * 5;. Para recordarlos necesitamos un lugar donde guardarlos. En el fondo, el entorno es un hash map de strings a objetos.

object/environment.go — primera versión
package object

func NewEnvironment() *Environment {
    s := make(map[string]Object)
    return &Environment{store: s}
}

type Environment struct {
    store map[string]Object
}

func (e *Environment) Get(name string) (Object, bool) {
    obj, ok := e.store[name]
    return obj, ok
}

func (e *Environment) Set(name string, val Object) Object {
    e.store[name] = val
    return val
}

Cambio de firma en todo el evaluador

El entorno debe viajar por cada llamada recursiva:

func Eval(node ast.Node, env *object.Environment) object.Object

Todas las funciones auxiliares (evalProgram, evalBlockStatement, evalIfExpression…) reciben ahora env.

En el REPL el entorno se crea fuera del ciclo for. Si se creara adentro, cada línea olvidaría las variables de la anterior.

2. Evaluar let e identificadores

case *ast.LetStatement:
    val := Eval(node.Value, env)
    if isError(val) {
        return val
    }
    env.Set(node.Name.Value, val)

case *ast.Identifier:
    return evalIdentifier(node, env)

func evalIdentifier(node *ast.Identifier, env *object.Environment) object.Object {
    val, ok := env.Get(node.Value)
    if !ok {
        return newError("identifier not found: " + node.Value)
    }
    return val
}

3. Funciones como objetos de primera clase

Una función en Monkey es un valor como cualquier otro: se guarda en variables, se pasa como argumento y se retorna. Necesita su propio tipo de objeto.

object/object.go
const FUNCTION_OBJ = "FUNCTION"

type Function struct {
    Parameters []*ast.Identifier
    Body       *ast.BlockStatement
    Env        *Environment
}

func (f *Function) Type() ObjectType { return FUNCTION_OBJ }
func (f *Function) Inspect() string {
    var out bytes.Buffer

    params := []string{}
    for _, p := range f.Parameters {
        params = append(params, p.String())
    }

    out.WriteString("fn")
    out.WriteString("(")
    out.WriteString(strings.Join(params, ", "))
    out.WriteString(") {\n")
    out.WriteString(f.Body.String())
    out.WriteString("\n}")

    return out.String()
}
evaluator/evaluator.go
case *ast.FunctionLiteral:
    params := node.Parameters
    body := node.Body
    return &object.Function{Parameters: params, Env: env, Body: body}

El campo que lo cambia todo: Env

La función guarda un puntero al entorno donde fue definida. Ese campo es lo que hace posibles los closures. Pregunta para la clase: ¿qué pasaría si no lo guardáramos?

4. Evaluar llamadas a funciones

evaluator/evaluator.go
case *ast.CallExpression:
    function := Eval(node.Function, env)
    if isError(function) {
        return function
    }
    args := evalExpressions(node.Arguments, env)
    if len(args) == 1 && isError(args[0]) {
        return args[0]
    }
    return applyFunction(function, args)

func evalExpressions(
    exps []ast.Expression,
    env *object.Environment,
) []object.Object {
    var result []object.Object

    for _, e := range exps {
        evaluated := Eval(e, env)
        if isError(evaluated) {
            return []object.Object{evaluated}
        }
        result = append(result, evaluated)
    }
    return result
}
evaluator/evaluator.go
func applyFunction(fn object.Object, args []object.Object) object.Object {
    function, ok := fn.(*object.Function)
    if !ok {
        return newError("not a function: %s", fn.Type())
    }

    extendedEnv := extendFunctionEnv(function, args)
    evaluated := Eval(function.Body, extendedEnv)
    return unwrapReturnValue(evaluated)
}

func extendFunctionEnv(
    fn *object.Function,
    args []object.Object,
) *object.Environment {
    env := object.NewEnclosedEnvironment(fn.Env)

    for paramIdx, param := range fn.Parameters {
        env.Set(param.Value, args[paramIdx])
    }
    return env
}

func unwrapReturnValue(obj object.Object) object.Object {
    if returnValue, ok := obj.(*object.ReturnValue); ok {
        return returnValue.Value
    }
    return obj
}
  1. Evalúa la expresión de la función (puede ser un identificador o un literal fn).
  2. Evalúa los argumentos de izquierda a derecha.
  3. Crea un entorno nuevo cuyo outer es fn.Env y liga parámetros → argumentos.
  4. Evalúa el cuerpo y desenvuelve el ReturnValue para que el return no “escape” de la función.

5. Entornos encerrados: el campo outer

Si al llamar fn(x) escribiéramos x directamente en el entorno global, sobrescribiríamos cualquier x existente. Por eso cada llamada recibe un entorno nuevo que envuelve al anterior.

object/environment.go — versión final
func NewEnclosedEnvironment(outer *Environment) *Environment {
    env := NewEnvironment()
    env.outer = outer
    return env
}

type Environment struct {
    store map[string]Object
    outer *Environment
}

func (e *Environment) Get(name string) (Object, bool) {
    obj, ok := e.store[name]
    if !ok && e.outer != nil {
        obj, ok = e.outer.Get(name)
    }
    return obj, ok
}
Monkey
let i = 5;
let printNum = fn(i) {
    puts(i);
};
printNum(10); // imprime 10
puts(i);      // imprime 5

6. Closures: funciones que recuerdan

Monkey
let newAdder = fn(x) {
    fn(y) { x + y };
};

let addTwo = newAdder(2);
addTwo(3); // => 5
  1. newAdder(2) crea el entorno E1 con x = 2 (outer = global).
  2. Al evaluar fn(y) { x + y } dentro de E1, el nuevo object.Function guarda Env = E1.
  3. newAdder termina, pero E1 sigue vivo porque addTwo.Env lo referencia.
  4. addTwo(3) crea E2 con y = 3 y outer = E1: encuentra x en E1.

E2 · llamada addTwo(3)

y3
outer →

E1 · capturado

x2
outer →

Global

newAdderfn(x)
addTwofn(y) · Env=E1
No escribimos código especial para closures. Salen solos de dos decisiones: (1) la función guarda Env al ser creada y (2) la llamada encierra fn.Env, no el entorno de quien la llama. Esto se llama alcance léxico.
Error común: usar el env del sitio de llamada en extendFunctionEnv. Eso produce alcance dinámico, y addTwo(3) fallaría con identifier not found: x.

7. Funciones de orden superior

Como las funciones son valores, pueden recibir y devolver otras funciones:

Monkey
let add = fn(a, b) { a + b };
let sub = fn(a, b) { a - b };
let applyFunc = fn(a, b, func) { func(a, b) };

applyFunc(2, 2, add); // => 4
applyFunc(10, 2, sub); // => 8
Más casos de prueba del libro
{"let identity = fn(x) { x; }; identity(5);", 5},
{"let identity = fn(x) { return x; }; identity(5);", 5},
{"let double = fn(x) { x * 2; }; double(5);", 10},
{"let add = fn(x, y) { x + y; }; add(5, 5);", 10},
{"let add = fn(x, y) { x + y; }; add(5 + 5, add(5, 5));", 20},
{"fn(x) { x; }(5)", 5},
Observa fn(x) { x; }(5): se llama a un literal de función directamente. Funciona porque la Semana 5 permitió que el lado izquierdo de una llamada sea cualquier expresión.

9. ¿Quién saca la basura? (Who's taking the trash out?)

Monkey
let counter = fn(x) {
    if (x > 100) {
        return true;
    } else {
        let foobar = 9999;
        counter(x + 1);
    }
};

counter(0);

Este programa crea más de 100 objetos Integer para foobar y para cada x + 1, además de un entorno por llamada. Nadie los libera explícitamente.

Respuesta: el runtime de Go

Nuestros objetos Monkey son valores Go comunes. Cuando ningún entorno ni objeto los referencia, el recolector de basura de Go los libera. Heredamos un GC de producción gratis.

¿Y si escribiéramos el intérprete en C?

Tendríamos que implementar nuestro propio GC (p. ej. mark & sweep): recorrer todos los objetos alcanzables desde los entornos vivos, marcarlos y liberar el resto. Es un proyecto completo por sí mismo.

Conexión con closures: el entorno E1 de newAdder(2) sigue vivo porque addTwo lo referencia. El GC solo puede liberarlo cuando addTwo deja de existir.

10. Ideas clave de la semana

Entorno = map + outer

Get busca hacia afuera; Set siempre escribe en el entorno actual.

Funciones son valores

object.Function guarda parámetros, cuerpo y el entorno de definición.

Llamar = encerrar

Cada llamada crea un entorno nuevo con outer = fn.Env.

Alcance léxico

Lo que una función “ve” depende de dónde fue escrita, no de dónde se llama.

Closures gratis

Surgen de capturar Env; no requieren un caso especial.

GC heredado

El recolector de Go libera objetos y entornos no alcanzables.

Hito del curso: con esto el intérprete es Turing completo: tiene variables, condicionales, funciones y recursión. Ya puedes escribir fibonacci en Monkey.
