Evaluación I: Objetos, Expresiones y Control

Hasta ahora 1 + 2 solo era un árbol. Hoy le damos significado: construimos un evaluador tree-walking que recorre el AST y produce valores reales.

Libro: Cap. 3.1 – 3.8 (pp. 103–135) Paquetes: object, evaluator REPL de Monkey en el navegador
1Comparar tree-walking, bytecode VM y JIT.
2Representar valores de Monkey con la interfaz object.Object.
3Evaluar prefijos, infijos, condicionales y return anidados.
4Propagar errores de ejecución sin romper el intérprete.

1. Dar significado a los símbolos

Evaluar es el paso en el que el código hace algo. La misma expresión 1 + 2 no significa nada hasta que un evaluador decide que el resultado es 3. Aquí también se define la semántica del lenguaje: ¿es 5 verdadero en un if? ¿se puede sumar un entero con un booleano?

Pseudocódigo de un evaluador tree-walking (del libro)
function eval(astNode) {
    if (astNode is integerliteral) {
        return astNode.integerValue
    } else if (astNode is booleanLiteral) {
        return astNode.booleanValue
    } else if (astNode is infixExpression) {
        leftEvaluated = eval(astNode.Left)
        rightEvaluated = eval(astNode.Right)

        if astNode.Operator == "+" {
            return leftEvaluated + rightEvaluated
        } else if ast.Operator == "-" {
            return leftEvaluated - rightEvaluated
        }
    }
}

2. Estrategias de evaluación

Tree-walking

Recorre el AST e interpreta cada nodo directamente. Simple y didáctico. Nuestro enfoque.

Ej.: el primer Ruby (MRI ≤ 1.8), muchos lenguajes de juguete y DSLs.

Bytecode + VM

Compila el AST a instrucciones compactas que ejecuta una máquina virtual. Mucho más rápido.

Ej.: CPython, Lua, YARV (Ruby ≥ 1.9). Tema de Writing A Compiler In Go.

JIT

Traduce a código máquina nativo justo antes o durante la ejecución.

Ej.: V8 (JavaScript), la JVM, LuaJIT, PyPy.

No hay una respuesta “correcta”: la elección depende de rendimiento, portabilidad y del lenguaje a interpretar. El libro elige tree-walking porque es la forma más directa de entender qué significa evaluar un programa — y es suficientemente rápida para Monkey.

3. El sistema de objetos (object/object.go)

Cada valor que aparece al evaluar se representa con un objeto que implementa una interfaz común. Así Eval siempre devuelve el mismo tipo: object.Object.

object/object.go
package object

import "fmt"

type ObjectType string

const (
    INTEGER_OBJ = "INTEGER"
    BOOLEAN_OBJ = "BOOLEAN"
    NULL_OBJ    = "NULL"
)

type Object interface {
    Type() ObjectType
    Inspect() string
}
object/object.go
type Integer struct {
    Value int64
}
func (i *Integer) Inspect() string  { return fmt.Sprintf("%d", i.Value) }
func (i *Integer) Type() ObjectType { return INTEGER_OBJ }

type Boolean struct {
    Value bool
}
func (b *Boolean) Inspect() string  { return fmt.Sprintf("%t", b.Value) }
func (b *Boolean) Type() ObjectType { return BOOLEAN_OBJ }

type Null struct{}
func (n *Null) Inspect() string  { return "null" }
func (n *Null) Type() ObjectType { return NULL_OBJ }
El “billion-dollar mistake”: Tony Hoare llamó así a la invención de la referencia nula. Monkey igual tiene null — el libro lo incluye a propósito para que aprendamos a manejarlo con cuidado.

4. Eval: la primera versión y sus pruebas

evaluator/evaluator.go
package evaluator

import (
    "monkey/ast"
    "monkey/object"
)

func Eval(node ast.Node) object.Object {
    switch node := node.(type) {

    // Sentencias
    case *ast.Program:
        return evalStatements(node.Statements)

    case *ast.ExpressionStatement:
        return Eval(node.Expression)

    // Expresiones
    case *ast.IntegerLiteral:
        return &object.Integer{Value: node.Value}
    }

    return nil
}

func evalStatements(stmts []ast.Statement) object.Object {
    var result object.Object
    for _, statement := range stmts {
        result = Eval(statement)
    }
    return result
}
evaluator/evaluator_test.go
func TestEvalIntegerExpression(t *testing.T) {
    tests := []struct {
        input    string
        expected int64
    }{
        {"5", 5},
        {"10", 10},
    }
    for _, tt := range tests {
        evaluated := testEval(tt.input)
        testIntegerObject(t, evaluated, tt.expected)
    }
}

func testEval(input string) object.Object {
    l := lexer.New(input)
    p := parser.New(l)
    program := p.ParseProgram()
    return Eval(program)
}

func testIntegerObject(t *testing.T, obj object.Object, expected int64) bool {
    result, ok := obj.(*object.Integer)
    if !ok {
        t.Errorf("object is not Integer. got=%T (%+v)", obj, obj)
        return false
    }
    if result.Value != expected {
        t.Errorf("object has wrong value. got=%d, want=%d",
            result.Value, expected)
        return false
    }
    return true
}
El type switch de la Semana 2 es todo el esqueleto del evaluador: switch node := node.(type) elige qué hacer según el tipo concreto de nodo. Cada nueva característica = un nuevo case.

5. Booleanos y Null: una sola instancia

Solo existen dos booleanos posibles y un único null. No tiene sentido crear un objeto nuevo cada vez: los definimos una vez y los reutilizamos.

evaluator/evaluator.go
var (
    NULL  = &object.Null{}
    TRUE  = &object.Boolean{Value: true}
    FALSE = &object.Boolean{Value: false}
)

// dentro del switch de Eval
case *ast.Boolean:
    return nativeBoolToBooleanObject(node.Value)

func nativeBoolToBooleanObject(input bool) *object.Boolean {
    if input {
        return TRUE
    }
    return FALSE
}

Beneficio doble

  • Memoria: no se crean miles de &object.Boolean{true} iguales.
  • Velocidad: comparar dos booleanos se reduce a comparar punteros (left == right), sin “desempacar” el valor.

Este truco lo usaremos en los infijos == y !=.

6. Operadores prefijos: ! y -

evaluator/evaluator.go
case *ast.PrefixExpression:
    right := Eval(node.Right)
    return evalPrefixExpression(node.Operator, right)

func evalPrefixExpression(operator string, right object.Object) object.Object {
    switch operator {
    case "!":
        return evalBangOperatorExpression(right)
    case "-":
        return evalMinusPrefixOperatorExpression(right)
    default:
        return NULL
    }
}

func evalBangOperatorExpression(right object.Object) object.Object {
    switch right {
    case TRUE:
        return FALSE
    case FALSE:
        return TRUE
    case NULL:
        return TRUE
    default:
        return FALSE
    }
}

func evalMinusPrefixOperatorExpression(right object.Object) object.Object {
    if right.Type() != object.INTEGER_OBJ {
        return NULL
    }
    value := right.(*object.Integer).Value
    return &object.Integer{Value: -value}
}

7. Operadores infijos: enteros y booleanos

evaluator/evaluator.go
case *ast.InfixExpression:
    left := Eval(node.Left)
    right := Eval(node.Right)
    return evalInfixExpression(node.Operator, left, right)

func evalInfixExpression(operator string, left, right object.Object) object.Object {
    switch {
    case left.Type() == object.INTEGER_OBJ && right.Type() == object.INTEGER_OBJ:
        return evalIntegerInfixExpression(operator, left, right)
    case operator == "==":
        return nativeBoolToBooleanObject(left == right)
    case operator == "!=":
        return nativeBoolToBooleanObject(left != right)
    default:
        return NULL
    }
}
evaluator/evaluator.go
func evalIntegerInfixExpression(operator string, left, right object.Object) object.Object {
    leftVal := left.(*object.Integer).Value
    rightVal := right.(*object.Integer).Value

    switch operator {
    case "+":
        return &object.Integer{Value: leftVal + rightVal}
    case "-":
        return &object.Integer{Value: leftVal - rightVal}
    case "*":
        return &object.Integer{Value: leftVal * rightVal}
    case "/":
        return &object.Integer{Value: leftVal / rightVal}
    case "<":
        return nativeBoolToBooleanObject(leftVal < rightVal)
    case ">":
        return nativeBoolToBooleanObject(leftVal > rightVal)
    case "==":
        return nativeBoolToBooleanObject(leftVal == rightVal)
    case "!=":
        return nativeBoolToBooleanObject(leftVal != rightVal)
    default:
        return NULL
    }
}
¡El orden de los case importa! left == right compara punteros. Funciona para booleanos (son singletons), pero no para enteros: dos &object.Integer{5} distintos tienen direcciones distintas. Por eso los enteros se revisan primero y se comparan por valor.

8. Condicionales y truthiness

evaluator/evaluator.go
case *ast.BlockStatement:
    return evalStatements(node.Statements)

case *ast.IfExpression:
    return evalIfExpression(node)

func evalIfExpression(ie *ast.IfExpression) object.Object {
    condition := Eval(ie.Condition)

    if isTruthy(condition) {
        return Eval(ie.Consequence)
    } else if ie.Alternative != nil {
        return Eval(ie.Alternative)
    } else {
        return NULL
    }
}

func isTruthy(obj object.Object) bool {
    switch obj {
    case NULL:
        return false
    case TRUE:
        return true
    case FALSE:
        return false
    default:
        return true
    }
}
ProgramaResultado

if (false) { 10 }null
if (1) { 10 }10
if (1 < 2) { 10 }10
if (1 > 2) { 10 } else { 20 }20

Truthy en Monkey

Todo lo que no sea null ni false es verdadero — incluso 0. Como el if es una expresión, un if sin else cuya condición es falsa produce null.

9. Sentencias return: envolver y desenvolver

Un return debe detener la evaluación del resto de sentencias. Lo logramos envolviendo el valor en un objeto especial que “burbujea” hacia arriba.

object/object.go + evaluator.go
const RETURN_VALUE_OBJ = "RETURN_VALUE"

type ReturnValue struct {
    Value Object
}
func (rv *ReturnValue) Type() ObjectType { return RETURN_VALUE_OBJ }
func (rv *ReturnValue) Inspect() string  { return rv.Value.Inspect() }

// evaluator.go
case *ast.ReturnStatement:
    val := Eval(node.ReturnValue)
    return &object.ReturnValue{Value: val}

func evalProgram(program *ast.Program) object.Object {
    var result object.Object
    for _, statement := range program.Statements {
        result = Eval(statement)
        if returnValue, ok := result.(*object.ReturnValue); ok {
            return returnValue.Value // ¡desenvuelve!
        }
    }
    return result
}

func evalBlockStatement(block *ast.BlockStatement) object.Object {
    var result object.Object
    for _, statement := range block.Statements {
        result = Eval(statement)
        if result != nil && result.Type() == object.RETURN_VALUE_OBJ {
            return result // NO desenvuelve: sigue burbujeando
        }
    }
    return result
}
El caso que obliga a separar las funciones
if (10 > 1) {
  if (10 > 1) {
    return 10;
  }
  return 1;
}
// debe producir 10, no 1
¿Por qué dos funciones? Si el bloque interno desenvolviera el ReturnValue, el bloque externo recibiría un simple 10, no sabría que hubo un return y seguiría hasta return 1;. Solo el nivel más alto (evalProgram) desenvuelve.

10. Abort! Abort! Manejo de errores

Devolver NULL ante 5 + true esconde el problema. Creamos un objeto de error que, igual que ReturnValue, detiene la evaluación y burbujea.

object/object.go + evaluator.go
const ERROR_OBJ = "ERROR"

type Error struct {
    Message string
}
func (e *Error) Type() ObjectType { return ERROR_OBJ }
func (e *Error) Inspect() string  { return "ERROR: " + e.Message }

// evaluator.go
func newError(format string, a ...interface{}) *object.Error {
    return &object.Error{Message: fmt.Sprintf(format, a...)}
}

func isError(obj object.Object) bool {
    if obj != nil {
        return obj.Type() == object.ERROR_OBJ
    }
    return false
}

// Ejemplo: revisar después de cada Eval
case *ast.InfixExpression:
    left := Eval(node.Left)
    if isError(left) {
        return left
    }
    right := Eval(node.Right)
    if isError(right) {
        return right
    }
    return evalInfixExpression(node.Operator, left, right)

12. Ideas clave de la semana

Eval = type switch

Un case por cada tipo de nodo del AST. Recursivo de principio a fin.

Todo es object.Object

Type() + Inspect() unifican enteros, booleanos, null, retornos y errores.

Singletons

TRUE, FALSE y NULL existen una sola vez y se comparan por puntero.

Truthiness

Solo null y false son falsos. 0 es verdadero.

Burbujeo

ReturnValue y Error suben por los bloques y solo evalProgram desenvuelve.

Semántica = decisiones

El evaluador es donde el diseñador del lenguaje decide qué significa cada operación.
