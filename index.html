1. ¿Por qué construir un Intérprete?

De texto plano a programas vivos

Un intérprete es un programa que lee, analiza y ejecuta otros programas. En lugar de tratar los lenguajes de programación como cajas negras mágicas, construiremos cada pieza desde cero para entender exactamente cómo una computadora le da sentido a caracteres, expresiones, funciones y memoria.

Bloque I · Go (Semanas 1–2 + módulos Go III–VI)

Aprenderemos exactamente el subconjunto de Go necesario para escribir software limpio y testeable:

  • Sintaxis, paquetes, slices y maps
  • Structs, punteros e interfaces implícitas
  • Funciones de primera clase y closures
  • Table-Driven Tests con go test
  • POO en Go: objetos, agregación, composición y embedding
  • Concurrencia: goroutines, canales, select y context
  • 22 patrones de diseño (GoF) aplicados al intérprete

Bloque II · Semanas 3 a 8 (Monkey)

Implementaremos un intérprete Tree-Walking completo siguiendo capítulo a capítulo el libro:

  • Lexer y REPL interactivo (Cap. 1)
  • AST y Parser Pratt de precedencia (Cap. 2)
  • Evaluador, Objetos, Entornos y Closures (Cap. 3)
  • Strings, Built-ins, Arrays y Hashes (Cap. 4)

2. Arquitectura y Pipeline del Intérprete

Todo el código escrito en Monkey atraviesa tres grandes transformaciones antes de producir un resultado en pantalla. Cada etapa tiene una responsabilidad única, pruebas unitarias propias y un paquete dedicado en Go:

Código Fuentelet x = 5 + 3 * 2;
→
Lexerpackage lexer
→
Tokenspackage token
→
Parser (Pratt)package parser / ast
→
Evaluadorpackage evaluator
→
Resultadopackage object

1. Análisis Léxico

Convierte una cadena cruda de caracteres en una secuencia limpia de Tokens etiquetados (LET, IDENT, INT, PLUS...).

2. Análisis Sintáctico

Organiza los tokens en un Árbol de Sintaxis Abstracta (AST) respetando reglas gramaticales y precedencia de operadores.

3. Evaluación

Recorre el AST (Tree-Walking), gestiona variables en entornos (Environment) y produce objetos en memoria.

3. Conoce el Lenguaje Monkey

Al finalizar la Semana 8, nuestro intérprete ejecutará programas funcionales reales con sintaxis tipo C, recursividad, closures y colecciones:

ejemplo_monkey.mk
// Variables, enteros, strings, arrays y hashes
let name = "Monkey";
let scores = [10, 20, 30];
let student = {"name": name, "grade": 5};

// Funciones de primera clase y retorno implícito
let add = fn(a, b) { a + b };

// Closures y funciones de orden superior
let newAdder = fn(x) {
    fn(y) { x + y }
};
let addTwo = newAdder(2);
addTwo(8); // => 10

Capacidades de Monkey

  • Sintaxis limpia inspirada en C y JavaScript
  • Enlaces de variables con let
  • Enteros, booleanos, null y strings
  • Expresiones aritméticas, prefijas e infijas con precedencia completa
  • Condicionales if / else como expresiones
  • Funciones de primera clase, orden superior y closures
  • Funciones integradas (len, first, last, rest, push, puts)
  • Estructuras de datos: Arrays y Hashes

Prueba ahora mismo el intérprete completo que construiremos. Escribe Monkey y recorre las tres fases: así se verá tu ZeldaInterpreter al final de la Semana 8.

5. Guías de Ejercicios para Estudiantes

Cada semana tiene una guía imprimible en PDF (carpeta ejercicios/pdf/) con la misma estructura, para que el estudiante sepa siempre qué esperar:

Parte A · Conceptos

Preguntas cortas y de selección para verificar que se entendió el por qué de cada decisión de diseño del libro.

Parte B · Trazas a mano

Tokenizar, dibujar ASTs, seguir la precedencia de Pratt o evaluar entornos en papel, antes de tocar el teclado.

Parte C · Programación

Retos en Go con firmas de funciones y casos de prueba esperados, más un reto opcional de extensión del lenguaje.

Cómo se usan: la Parte A y B se pueden resolver en clase o como quiz; la Parte C es el entregable semanal (repositorio con go test ./... en verde). Cada guía incluye una rúbrica de evaluación al final.

6. Metodología del Curso y Referencia

Desarrollo Guiado por Pruebas (TDD)

Siguiendo la filosofía del libro, cada característica del intérprete se construye bajo el mismo ciclo:

  1. Definimos el comportamiento esperado en un *_test.go.
  2. Ejecutamos go test ./... y observamos la falla.
  3. Implementamos el código mínimo y limpio para pasar las pruebas.
  4. Refactorizamos y probamos en el REPL interactivo.

Estructura Final del Proyecto

zeldainterpreter/
zeldainterpreter/
├── go.mod
├── main.go          # Línea de comandos: archivo, stdin, -e, -modo
├── token/           # Definición de tokens (Sem 3)
├── lexer/           # Análisis léxico (Sem 3)
├── ast/             # Nodos del AST + dibujante de árboles (Sem 4-5)
├── parser/          # Pratt Parser (Sem 4-5)
├── object/          # Sistema de objetos y Environment (Sem 6-8)
├── evaluator/       # Tree-Walking Evaluator + built-ins (Sem 6-8)
├── runner/          # Modos: eval, tokens, ast, arbol
├── repl/            # Consola interactiva con comandos
└── programas/       # Ejemplos .mk
Tip para usar este sitio en clase: Cada semana tiene un botón Modo Presentación (o tecla P) que convierte la página en diapositivas limpias con barra de progreso y navegación por teclado (← / → / Esc). Para estudiar después de clase, el modo guía permite leer, copiar código y consultar referencias con scroll continuo.

7. Cómo correr ZeldaInterpreter

El intérprete de referencia está en la carpeta zeldainterpreter/. Necesitas Go 1.23 o superior. Todos los comandos se escriben dentro de esa carpeta; las opciones (-modo, -e…) van antes del nombre del archivo.

Cómo se llamaQué hace
go run .Abre la consola interactiva (REPL). :ayuda lista sus comandos.
go run . programa.mkEjecuta un archivo .mk.
go run . -e "código"Ejecuta código escrito en la línea de comandos.
cat programa.mk | go run . -Ejecuta lo que llegue por la entrada estándar.
-modo=tokens | ast | arbol | evalElige hasta qué fase llega: lexer, parser (texto o árbol) o evaluación completa.
go build -o zelda .Compila el ejecutable zelda (en Windows zelda.exe); luego ./zelda programa.mk.
